# S-135: AI-фаза — разбор состояния, направления, рекомендации (скоуп под решение человека)

## 1. Что есть сейчас (факты, не декларации)

- **D1–D4 работают в проде**: `internal/application/assistant/` — design/engineering/manufacturing/pricing эксперты, детерминированные ответы (`Response`: recommendation/rating/alternatives/findings/suggestions), комментарий — локальный детерминированный либо LLM через `STAIR_AI_*` (`openai.go`, stdlib, OpenAI-совместимый API: OpenAI/Anthropic-gateway/Ollama/vLLM). Фолбэк primary → local (AI-0003). Каждый запрос аудируется (`ai.assist.*`), в промпт — только структурные данные без PII (AI-0001/AI-0012).
- **Транспорт**: `POST /api/v1/assistant/{kind}` за auth, swagger описан; фронт — `AssistantPanel.tsx` (4 таба) в ProjectDetail; тесты есть с обеих сторон.
- **Чего НЕТ (несмотря на APPROVED-статусы доков)**: RAG-движка (нет эмбеддингов, чанкинга, retriever'а; pgvector в БД нет — только pgcrypto; поиск — tsvector/GIN FTS), Memory Engine (нет conversation/project-памяти; есть только audit-лог как побочный след), Agent Framework/Planning (Ask = один проход analyze→comment, без циклов plan→act→validate), tool-calling со стороны LLM (наш «Tool Calling» — это внутренние Go-вызовы экспертов, модель тулы НЕ вызывает).

## 2. Куда можем прийти (лестница зрелости, каждая ступень — отдельная ценность)

1. **RAG на документации/стандартах** (AI-0007): чанкинг docs+нормативов → эмбеддинги → pgvector (расширение в RDS доступно) → retriever в контекст экспертов. Ценность: ассистент отвечает со ссылками на пункты СНиП/ГОСТ, а не «из головы»; галлюцинации падают.
2. **Conversation/Project memory** (AI-0006): хранение диалога и контекста проекта (таблица + TTL + скоупы user/project/org). Ценность: «а теперь удешеви на 10%» — без повторного ввода конфигурации; мультишаговые уточнения.
3. **LLM tool-calling наружу** (AI-0008 по-настоящему): модель сама вызывает Calculate/Optimize/Validate/Search через JSON-schema тулов в цикле. Ценность: свободные вопросы («влезет ли такая лестница в проём 2.5м?») вместо 4 фиксированных кнопок.
4. **Агентные циклы** (AI-0009/AI-0010): планировщик plan→act→validate с лимитами шагов/бюджета, саб-агенты (Review/Documentation). Ценность: «спроектируй под бюджет X» как одна задача.
5. **Обучение на своих данных**: eval-набор (golden Q/A по лестницам) → метрики качества → файнтюн/дообучение эмбеддингов. Ценность: отстройка от конкурентов; дорого, только при наличии трафика.

## 3. Честные риски/цены каждой ступени

- **Деньги**: эмбеддинги ~$0.02/1M токенов (дешево), chat-инференс $0.5–15/1M (зависит от модели) — при нашей нише объёмы малые, счёт будет десятки $/мес; self-hosted (Ollama/vLLM) — $0 за токены, но +GPU-нода ~$200–500/мес и возня. RAG-инфра (pgvector) — $0 (тот же RDS).
- **Латентность**: RAG добавляет ~0.3–1.5с (эмбеддинг+поиск); агентные циклы — 10–60с на задачу (нужен WS-стриминг прогресса — задел S-132 как раз даёт комнаты pipeline:*).
- **Безопасность**: LLM tool-calling = новый класс атак (prompt injection → вызов тулов; модель может «выдумать» параметры). Наши guardrails (детерминированная структура ответа, аудит, PII-фильтр) — правильное ядро, его надо расширять, а не ломать: валидация каждого tool-call против JSON-schema + лимиты + human-in-the-loop на мутирующих действиях.
- **Качество**: без eval-набора любой «умный» шаг — вкусовщина. Golden-набор из ~50–100 вопросов с эталонными ответами — обязательный пререквизит ступеней 3–5.

## 4. Рекомендации (блок для решения человека)

- **R1 (стратегия)**: идти строго по ступеням 1→2→3, не прыгать в агентов. RAG даёт максимум ценности за минимум риска и почти $0 инфры.
- **R2 (MVP-скоуп S-135)**: Этап A — RAG на docs/13_AI + инженерных доках + EDR/ADR (корпус уже лежит в репо, версионирован — идеально по AI-0007 «только проверенные источники»): pgvector-миграция, чанкер, эмбеддер (env STAIR_AI_EMBED_*), retriever в `Ask`, цитаты источников в `Response`. Этап B — conversation-memory (таблица, TTL, скоуп project) + eval-набор ~50 Q/A. Этапы tool-calling наружу и агентные циклы — отдельными задачами после eval-зелени.
- **R3 (модель, решение человека 2026-09-23)**: вендор — **OpenRouter** (один API-ключ, OpenAI-совместимый `https://openrouter.ai/api/v1` → втыкается в существующий `openai.go` через `STAIR_AI_BASE_URL`, смена модели — env `STAIR_AI_MODEL` без кода). Старт: дешёвая модель для комментариев + сильная для сложных разборов (роутинг по kind через ModelRouter). Нюансы: +100–300мс хопа, небольшой markup к ценам провайдеров, данные идут через третью сторону (приемлемо pre-launch; для прода проверить zero-retention опции). Пересмотр в self-hosted — при счёте >$300/мес 3 месяца подряд.
- **R4 (что НЕ делать)**: не тащить LangChain/фреймворки (наша архитектура чище и уже покрыта тестами); не давать LLM прямых мутаций (заказы/проекты) без human-in-the-loop; не файнтюнить до первых 10k реальных диалогов.
- **R5 (DoD для S-135)**: eval-набор green (порог % зафиксировать), p95 Ask+RAG < 5с, аудит каждого RAG-ответа (какие чанки использованы), доки AI-0007 из APPROVED-декларации → в рабочий runbook.
