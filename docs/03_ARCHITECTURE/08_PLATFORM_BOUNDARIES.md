# Purpose

Документ определяет архитектурные границы (Boundaries) всех платформ STAIR Platform.

Границы платформ являются обязательными.

Изменение границ допускается только через ADR.

---

# Objectives

- исключить пересечение ответственности;
- минимизировать связанность;
- обеспечить независимое развитие платформ;
- определить владельца каждой области ответственности.

---

# Boundary Principles

Single Responsibility

High Cohesion

Loose Coupling

Information Hiding

Contract First

API First

---

# Platform Ownership

Foundation

Ответственность:

- правила проекта;
- стандарты;
- инженерные процессы.

Не отвечает за:

- бизнес-логику;
- вычисления.

---

Product

Ответственность:

- продуктовые возможности;
- пользовательские сценарии;
- функциональные требования.

---

Domain

Ответственность:

- предметная область;
- бизнес-сущности;
- правила предметной области.

---

Architecture

Ответственность:

- архитектурные правила;
- взаимодействие платформ;
- зависимости;
- ограничения.

---

Engine

Ответственность:

- выполнение вычислений;
- orchestration;
- execution pipeline.

Не отвечает за хранение данных.

---

Geometry

Ответственность:

- математическая модель;
- параметрика;
- геометрические операции.

Не отвечает за стоимость.

Не отвечает за производство.

---

Manufacturing

Ответственность:

- BOM;
- CNC;
- производство;
- материалы.

Не отвечает за геометрическое ядро.

---

Pricing

Ответственность:

- стоимость;
- коммерческие расчеты;
- скидки;
- налоги.

Не изменяет Geometry.

---

API

Ответственность:

- публикация контрактов;
- безопасность;
- интеграция.

Не содержит бизнес-логики.

---

Database

Ответственность:

- хранение данных.

Не содержит бизнес-логики.

---

AI

Ответственность:

- интеллектуальные сервисы.

Не принимает архитектурных решений самостоятельно.

---

# Boundary Rules

Каждая платформа имеет собственного владельца.

Каждая платформа имеет собственную модель данных.

Каждая платформа публикует только API.

---

# Forbidden

Запрещается:

- обход API;
- изменение внутренних моделей других платформ;
- использование внутренних Entity;
- обращение к чужим БД;
- создание циклических зависимостей.

---

# Acceptance Criteria

- определены границы всех платформ;
- отсутствует пересечение ответственности;
- отсутствуют циклические зависимости.
