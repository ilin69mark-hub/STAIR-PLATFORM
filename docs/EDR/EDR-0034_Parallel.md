# 1. Purpose

Документ фиксирует Parallel Execution (Phase B, B3) — третий элемент
Engineering Expansion bounded context (BC-002). Цель — использовать
многоядерность для независимых циклов конвейера без потери детерминизма:

1. **Scheduler.Execute** — ограниченный параллельный исполнитель задач по
   слотам (result-slot): задача `i` записывает результат в слот `i`,
   ошибка возвращается детерминированно (первый по индексу слот с ошибкой
   или отмена контекста). Это примитив для всех параллельных стадий.
2. **Build-циклы geometry** — построение твёрдых тел марша (косоуры,
   проступи, подступенки) независимо; параллелится через Scheduler,
   порядок тел в Compound фиксирован индексами слотов.
3. **Per-material Nest** — раскрой по группам (материал, толщина)
   независим; группы раскладываются параллельно, листы собираются в
   порядке групп.
4. **Geometry.Generate** — обработка тел (валидация, объём, площадь,
   mesh) переводится на Scheduler (была errgroup): детерминированная
   ошибка первого по индексу сбоя.

Результат параллелизации эквивалентен последовательному (тот же набор
выходов), но использует доступные ядра. Детерминизм — ADR-0003: слоты
индексируются заранее, сборка идёт по порядку индексов, ошибки — по
первому индексу.

# 3. Model

## 3.1 Scheduler.Execute

Новый пакет `internal/engine/scheduler`:

```go
type Scheduler struct{ limit int }
func New(limit int) *Scheduler     // limit <= 0 → GOMAXPROCS(0)
func (s *Scheduler) Execute(ctx context.Context, n int, fn func(i int) error) error
```

- `fn(i)` для `i ∈ [0, n)` запускается с ограниченным параллелизмом
  (semaphore-пул).
- `limit == 1` или `n <= 1` — последовательный путь (без оверхеда
  goroutine).
- Каждая задача пишет свой результат/ошибку в слот `i`; после завершения
  всех задач возвращается первый по возрастанию индекса слот с ошибкой,
  иначе `nil`.
- Отмена контекста: задачи, ещё не начавшие работу, помечают свой слот
  `ctx.Err()`; возвращается `context.Canceled`/`DeadlineExceeded`.
- Детерминизм: ошибка выбирается по индексу, а не по порядку завершения
  goroutine.

## 3.2 Build-циклы geometry

`BuildStraightFlight` строит `2n+2` тела (2 косоура, n проступей,
n подступенков) независимо: слайс замыканий (slot → build+Extrude)
запускается Scheduler'ом, тела собираются в Compound в порядке слотов.
L/U-марши наследуют параллелизм через свои вызовы BuildStraightFlight.
Порядок тел в Compound не меняется → декомпозиция (MFG) и тесты
детерминированы.

## 3.3 Per-material Nest

`Nest` группирует CutList по (material, thickness). Каждая группа:
`pickSheet` (независимо) → `nestGroup` (независимо). Группы раскладываются
параллельно, layout-ы каждой группы складываются в слот, затем
собираются в итоговый `NestingResult` в порядке `order` (первое
появление группы) — тот же результат, что и последовательный обход.
Агрегаты (SheetArea/PartArea/Utilization) коммутативны и собираются
последовательно после завершения групп.

## 3.4 Geometry.Generate

Обработка тел (ValidateCached → VolumeCached → SurfaceAreaCached →
meshSolid) переводится с `errgroup` на `Scheduler.Execute`: результат —
первый по индексу сбой (детерминированно) либо отмена контекста.
Пулы и кеши граней сохраняются.

# 4. Security

- Параллелизм ограничен `GOMAXPROCS(0)` — нет неограниченных пулов.
- Данные только в памяти, тенанты не затрагиваются; результатов в
  выходных данных не меняется — поверхность атак та же.
- Отмена контекста (EDR-0033) действует и на параллельные стадии.

# 5. Acceptance

1. `go build ./...`, `go vet ./...`, `gofmt -w` — чисто.
2. Scheduler: юнит-тесты (последовательный путь, параллельный путь,
   ошибка первого по индексу слота, отмена контекста).
3. Geometry: существующие юнит-тесты (все типы маршей) проходят без
   изменения выходов; бенчмарк `BenchmarkGeometryBuild`/`BenchmarkTriangulate`
   не деградирует.
4. Manufacturing: существующие тесты Nest/Manufacture проходят; бенчмарк
   `BenchmarkNest` не деградирует.
5. Параллельный результат равен последовательному (тест-инвариант).
6. ROADMAP: «Parallel Execution — DONE 2026-08-15».
