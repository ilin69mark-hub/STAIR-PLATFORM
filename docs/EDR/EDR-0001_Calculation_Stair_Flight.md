Документ является единственным источником инженерных формул (ADR-0003) для платформенного расчёта лестниц.

# 4. Formulas

Все вычисления на `float64`, без внутренних округлений (ADR-0008).
Точность геометрии — 1e-6 мм. Округления допускаются только на границе
(отображение, документация, API).

## 4.1 Число ступеней

```
n = round(H / h)          (n ≥ 1, целое)
```

## 4.2 Уточнённая высота ступени

```
h = H / n
```

## 4.3 Проступь (формула удобства)

```
b = S − 2h
```

Константа `S` — шаг комфорта. Нормативное значение: 600 ≤ S ≤ 640 мм
(по умолчанию S = 630 мм).

## 4.4 Угол наклона

```
α = atan(h / b)
```

Внутренняя единица угла — радиан; градусы только для отображения.

## 4.5 Длина марша по горизонтали

```
L = n · b
```

### 4.5.1 Конвенция подсчёта (зафиксирована 2026-09-26, DOM-004)

**n — число ПРОСТУПЕЙ марша. Нижний (и верхний) пол ступенью НЕ считаются.**

Марш начинается первым подступенком: первая проступь занимает
`[0, b]` на уровне `h`, последняя — `[L−b, L]` на уровне `n·h`. Поэтому
горизонтальный размер марша равен `n·b`, а не `(n−1)·b`.

Формула `(n−1)·b` применяется в другой модели отсчёта — когда нижний пол
считается первой ступенью, а последняя ступенью является верхней площадкой.
**Эта модель в платформе не используется**, и смешивать их нельзя: результат
расходится на целую проступь `b` в длине марша, длине косоура, раскрое и цене.

Инвариант, который обязан выполняться во всех слоях (solver, геометрия,
производство, API, фронтенд), проверяется тестом
`TestDOM004_FlightRunMatchesNB` (internal/engine/geometry):

```
правый край геометрии марша по X = L = n · b
ширина bbox по X = n · b + st   (st — толщина ступени, свес назад)
длина косоура по раскрою = n · b
```

Изменение конвенции — это изменение спецификации (ADR-0003): правки
должны идти синхронно в EDR-0001 §4.5.1, EDR-0005 §4.6, EDR-0006 §4.6,
`solver.Solve`, `geometry.stringerProfile` и в зафиксированные ожидания тестов.

## 4.6 Длина косоура

```
R = sqrt(L² + H²)
```

# 5. Determinism

Формулы детерминированы: при равных входных параметрах результат строго идентичен.

Порядок пересчёта результата через Graph Scheduler (ADR-0012):
предки → потомки, каждый узел выполняется не более одного раза за проход.

---

# 6. Precision

- входные/выходные значения: `float64`;
- геометрическая точность: 1e-6 мм;
- никаких промежуточных округлений внутри расчёта.

---

# 7. Tests

- Unit тесты формул (каждый пункт §4);
- determinism: повторный запуск даёт идентичный результат;
- edge cases: высота без участка (n < 1) → ошибка валидации;
- интеграция с Validation Engine (EDR-0003).
