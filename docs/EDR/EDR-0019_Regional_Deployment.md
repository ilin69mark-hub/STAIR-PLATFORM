# 1. Purpose

Документ фиксирует региональное развёртывание (Phase H, H2) — поддержку
запуска инстансов в нескольких регионах (data residency, локальность,
отказоустойчивость) и разграничение регионально-зависимой конфигурации.
Скоуп H2:

1. **Региональный конфиг-слой** — `STAIR_REGION` как первичный маркер
   региона инстанса; регион прокидывается в логи и метаданные (для H4 —
   метки метрик, для аудита — источник запроса).
2. **Регионально-зависимые настройки** — часовой пояс по умолчанию,
   локаль, единицы измерения (где применимо) — выделяются из хардкода в
   конфиг.
3. **Инфраструктурная документация** — топология multi-region (PRIMARY /
   read-replica, edge/DNS), схемы развёртывания (blue/green, canary),
   пример docker-compose с region-метками.

Реализация — офлайн-безопасна, без новых внешних зависимостей.

# 3. Model

## 3.1 Региональный конфиг

```yaml
region: "eu-central-1"        # STAIR_REGION
default_timezone: "UTC"       # STAIR_TZ (опционально)
default_locale: "ru-RU"       # STAIR_LOCALE (опционально)
```

| Env | Deфолт | Описание |
|-----|--------|----------|
| `STAIR_REGION` | `""` | Идентификатор региона инстанса (например `eu-west-1`, `us-east-1`). Пусто — не задан |
| `STAIR_TZ` | `UTC` | Часовой пояс по умолчанию (для отображения времени) |
| `STAIR_LOCALE` | `ru-RU` | Локаль по умолчанию |

`STAIR_REGION` — обязательный маркер в production multi-region сценарии.
Если задан, значение отображается в `/health`, логах старта и (для H4)
как label `region` в `/metrics`.

## 3.2 Принцип региона в приложении

- **Stateless + shared DB/Redis** (EDR-0018): инстансы в разных регионах
  используют общий Postgres (PRIMARY) и общий Redis. Недоступность
  локальной реплики не останавливает API — только готовность задач,
  зависящих от локальных ресурсов.
- **Обязательные зависимости** (БД/Redis) проверяются через `/ready`
  (EDR-0018); региональные ресурсы — через отдельные пробы при наличии.
- **Регион — тег, а не бизнес-логика**: сам по себе не меняет поведение
  сервиса; влияет только на наблюдаемость (метрики/логи) и выбор
  дефолтных локалей.

## 3.3 Топология развёртывания

```
                    ┌────────────────────────────┐
   Edge/DNS ───────▶│ LB (реплики API)           │
                    │  - /health (liveness)      │
                    │  - /ready  (readiness)     │
                    └───────┬────────┬───────────┘
                            │        │
                     ┌──────▼──┐ ┌───▼──────┐
                     │  api-1  │ │  api-N   │  (каждый: STAIR_REGION, INSTANCE_ID)
                     └────┬────┘ └────┬─────┘
                          │           │
                     ┌────▼────────────▼─────┐
                     │  PostgreSQL (PRIMARY)  │──▶ read replicas (per region, optional)
                     │  Redis (shared)        │
                     └────────────────────────┘
```

- **LB-пробы**: `/health` для liveness (всегда 200), `/ready` для
  readiness (200 только при доступных БД/Redis) — EDR-0018.
- **Blue/green**: две full-стек-окружения (current/next) + переключение на
  edge/DNS; `/ready` позволяет новому green сниматься, пока не готов.
- **Canary**: постепенное расширение доли трафика на новую реплику/регион
  через взвешенный LB.

## 3.4 Документация развёртывания

Предоставляется в `deployments/`:

- `deployments/multi-region.example.yml` — пример docker-compose с
  region-метками, несколькими api-инстансами, shared postgres/redis.
- `deployments/README.md` — схемы blue/green, canary, LB-пробы, рекомендации
  по DNS/edge.

# 4. Invariants

```
1. STAIR_REGION, если задан, отображается в /health и логах старта.
2. Регион — наблюдаемостный тег; не меняет бизнес-логику сервиса.
3. Инстансы остаются stateless (EDR-0018); региональность не вводит
   локального состояния пользователя.
4. Обязательные зависимости едины (общий Postgres/Redis); отказ локальной
   реплики влияет только на соответствующие задачи, не на базовую работу API.
5. Все региональные настройки имеют безопасные дефолты (пустой регион =
   работа без региона).
```

# 6. API

Изменений API нет. Регион отражается в:

- `GET /health` → поле `region` (если задан);
- лог старта `cmd/api` → `region`;
- `GET /metrics` (H4) → label `region` (если задан).
