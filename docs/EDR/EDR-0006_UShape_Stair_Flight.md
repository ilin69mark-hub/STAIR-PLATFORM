# 3. MDL (Math Model)

## Концепция

П-образная лестница состоит из:

- **нижнего марша** (straight, нижняя секция);
- **верхнего марша** (straight, верхняя секция), параллельного нижнему и
  идущего в противоположном направлении (разворот на 180° по горизонтали
  относительно нижнего);
- **площадки** (landing) — горизонтального прямоугольного элемента между
  маршами на высоте окончания нижнего марша.

Каждый марш рассчитывается по формулам EDR-0001 §4 (прямой марш).
Площадка не влияет на разбивку ступеней (не добавляет ступеней).

Разбивка ступеней и габариты секций идентичны L-образному маршу
(EDR-0005 §4): П-образный марш отличается от L-образного только углом
поворота верхнего марша (180° вместо 90°).

## Входные параметры (SSOT, единицы ADR-0008)

| Symbol | Description | Unit |
|--------|-------------|------|
| H | общая высота подъёма (rise) | mm |
| W | ширина марша (ширина каждой секции) | mm |
| h0 | целевая высота ступени (riser) | mm |
| S | шаг комфорта (пользовательская или нормативная константа) | mm |
| n1 | число ступеней нижнего марша | шт. (int) |
| Wp | ширина площадки (в плане, между маршами) | mm |
| t | толщина косоура (stringer) | mm |
| st | толщина ступени (step thickness, EDR-0004) | mm |
| cl | вертикальный просвет (clearance) | mm |
| rh | высота ограждения (railing height) | mm |

## Выходные значения

| Symbol | Description | Unit |
|--------|-------------|------|
| n | общее число ступеней | шт. (int) |
| n1 | число ступеней нижнего марша | шт. (int) |
| n2 | число ступеней верхнего марша | шт. (int) |
| h | уточнённая высота ступени (общая для обоих маршей) | mm |

| H2 | высота окончания верхнего марша (= H) | mm |

# 4. Formulas

Все вычисления на `float64`, без внутренних округлений (ADR-0008).
Точность геометрии — 1e-6 мм. Округления допускаются только на границе
(отображение, документация, API).

## 4.1 Число ступеней

```
n = round(H / h0)          (n ≥ 1, целое)
```

## 4.2 Уточнённая высота ступени

```
h = H / n
```

## 4.3 Проступь (формула удобства)

```
b = S − 2h
```

Константа `S` — шаг комфорта. Нормативное значение: 600 ≤ S ≤ 640 мм
(по умолчанию S = 630 мм), как в EDR-0001 §4.3.

## 4.4 Угол наклона

```
α = atan(h / b)
```

## 4.5 Разбивка по маршам

Входное значение n1 (число ступеней нижнего марша) фиксируется
пользователем; верхний марш получает остальные ступени:

```
n2 = n − n1
```

Инварианты:

```
1 ≤ n1 ≤ n − 1
n2 ≥ 1
```

Высоты секций:

```
H1 = n1 · h
H2 = n2 · h
H = H1 + H2
```

## 4.6 Длины маршей по горизонтали

```
L1 = n1 · b
L2 = n2 · b
```

Конвенция подсчёта — EDR-0001 §4.5.1: n1/n2 — числа ПРОСТУПЕЙ каждого
марша, пол ступенью не считается, поэтому длина равна n·b, а не (n−1)·b.

## 4.7 Длины косоуров

```
R1 = sqrt(L1² + H1²)
R2 = sqrt(L2² + H2²)
```

## 4.8 Площадка и раскладка маршей

Площадка — горизонтальный прямоугольник толщиной `st` (как проступь,
EDR-0004) на высоте `H1`. Ширина площадки `Wp` (в плане, направление
поворота 180°) — входной параметр.

Инвариант:

```
Wp ≥ W
```

### 4.8.1 Фактическая раскладка (уточнена 2026-09-26, DOM-004/S1)

Марш строится функцией `geometry.uShapePlatformTransforms` — она ЕДИНАЯ
для ступеней и перил, поэтому перила гарантированно совпадают со ступенями.
Разделение маршей (зазор `flightSideInsetMM` = 100 мм) делается сужением
маршей до `wEff = W − 100`, а площадка остаётся шириной `2·W`.

**Поворот вправо (по умолчанию):**

```
нижний марш:  план [0, L1] × [0, wEff]
площадка:     план [L1, L1+W] × [0, 2W]
верхний марш: T_upper = Translate(L1, 2W, H1) · RotateZ(π)
              → план [L1−L2, L1+st] × [W+100, 2W]
```

Итоговый габарит: `X ∈ [min(0, L1−L2), L1+W]`, `Y ∈ [0, 2W]`.

**Поворот влево** (зеркально по X, `landingX0 = 0`):

```
нижний марш:  план [W, W+L1+st] × [0, wEff]
площадка:     план [0, W] × [0, 2W]
верхний марш: T_upper = Translate(W, W+100, H1)
              → план [W−st, W+L2] × [W+100, 2W]
```

**Важно (отличие от классического switchback):** узел поворота собран в ОДНОМ
углу площадки, а не «через всю площадку». Поэтому верхний марш по X начинается
с `L1−L2` и при `L2 > L1` выходит в отрицательные X — это нормально
(`L1−L2 = −810 мм` при L1=1620, L2=2430). Габарит для проверки вписывания
в помещение берётся ИЗ ФАКТИЧЕСКОГО BBOX 3D-модели
(`geometry/engine.go` fit-check), а не из суммы L1+L2+Wp.

Площадка не добавляет ступеней и не изменяет разбивку маршей.

# 5. Determinism

Формулы детерминированы: при равных входных параметрах результат строго
идентичен (наследует детерминизм EDR-0001).

Порядок пересчёта результата через Graph Scheduler (ADR-0012):
предки → потомки, каждый узел выполняется не более одного раза за проход.

# 7. Tests

- Unit тесты формул (каждый пункт §4);
- determinism: повторный запуск даёт идентичный результат;
- edge cases: n < 1 → ошибка; n1 = 0 или n1 = n → ошибка разбивки;
  Wp < W → ошибка;
- интеграция с Validation Engine (EDR-0003): правила EDR-0002
  применяются к обоим маршам.
