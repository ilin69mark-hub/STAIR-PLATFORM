# 1. Context

Stair Platform является инженерной платформой.

В процессе разработки накапливаются:

- инженерные алгоритмы;
- математические модели;
- расчетные формулы;
- нормативные требования;
- производственные ограничения;
- исследования;
- инженерные решения;
- практические знания.

Хранение этих знаний исключительно в исходном коде или документации приводит к их постепенной утрате.

Необходимо централизованное хранилище инженерных знаний.

---

# 2. Problem

При отсутствии единой базы знаний возникают следующие проблемы:

- повторная разработка уже существующих решений;
- потеря инженерного опыта;
- невозможность повторного использования алгоритмов;
- сложность обучения новых разработчиков;
- отсутствие единого инженерного словаря.

---

# 3. Decision

В проект вводится отдельная подсистема:

**Engineering Knowledge Base (EKB).**

EKB становится единым источником инженерных знаний Stair Platform.

---

# 4. Цели Engineering Knowledge Base

EKB обеспечивает:

- накопление инженерных знаний;
- повторное использование решений;
- единый инженерный словарь;
- документирование алгоритмов;
- документирование математических моделей;
- документирование производственных правил;
- поддержку AI-модулей.

---

# 5. Состав Engineering Knowledge Base

EKB включает:

- инженерные алгоритмы;
- математические модели;
- формулы;
- ограничения;
- стандарты;
- производственные правила;
- CAD-правила;
- CNC-правила;
- рекомендации;
- примеры расчетов.

---

---

# 7. Связь с другими документами

Каждый элемент EKB должен иметь ссылки на:

- EDR;
- ADR;
- FR;
- инженерные алгоритмы;
- тесты;
- примеры.

---

# 8. Правила ведения

Каждый новый инженерный алгоритм обязан сопровождаться:

- описанием;
- математическим обоснованием;
- примером;
- ограничениями применения;
- ссылками на EDR.

---

# 9. Использование AI

Engineering Knowledge Base является основным источником контекста для AI.

AI не должен использовать инженерные знания, отсутствующие в EKB, без явного подтверждения пользователя.

---

# 10. Consequences

Преимущества:

- накопление инженерной экспертизы;
- сокращение повторной работы;
- повышение качества алгоритмов;
- ускорение разработки;
- единый источник инженерных знаний.

Недостатки:

- необходимость сопровождения;
- увеличение объема документации.

---

# 11. Alternatives Considered

## Хранение знаний только в коде

Отклонено.

Причина:

знания становятся труднодоступными.

---

## Использование Wiki

Отклонено.

Причина:

отсутствие строгой структуры и трассируемости.

---

## Использование только EDR

Отклонено.

Причина:

EDR фиксирует решения, но не является базой знаний.

---

# 12. Implementation

После принятия ADR:

- создается каталог `EKB/`;
- вводится шаблон инженерной статьи;
- все новые инженерные знания документируются в EKB;
- AI использует EKB как основной источник инженерного контекста.
