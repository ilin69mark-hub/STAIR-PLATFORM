# Purpose

Определяет обязательную структуру Development Task.

---

# Required Fields

Каждая значимая task должна содержать:

* ID
* Title
* Context
* Objective
* Scope
* Acceptance Criteria
* Dependencies
* Priority

---

# ID

Каждая task имеет уникальный идентификатор.

---

# Title

Title должен кратко описывать действие или результат.

---

# Context

Описывает причину появления task.

---

# Objective

Определяет ожидаемый результат.

---

# Scope

Должно быть явно указано:

* In Scope
* Out of Scope

---

# Acceptance Criteria

Критерии должны быть проверяемыми.

---

# Dependencies

Указываются зависимости от:

* Other Tasks
* Architecture
* Database
* API
* Infrastructure
* External Systems

---

# Priority

Используется установленная priority model.

---

# Technical Notes

При необходимости task может содержать:

* Technical Approach
* Risks
* Testing Strategy
* Migration Notes

---

# Acceptance Criteria

Development Task содержит достаточно информации для начала реализации без неоднозначного interpretation.
