# 1. Назначение

Настоящий документ определяет критерии успешности Stair Platform.

Критерии используются для оценки степени достижения целей проекта на всех этапах жизненного цикла.

Настоящий документ является основой для оценки качества продукта, архитектуры и процесса разработки.

---

# 2. Цель

Документ отвечает на вопросы:

- когда проект можно считать успешным;
- какие показатели являются обязательными;
- какие метрики используются для оценки;
- какие критерии являются приоритетными.

---

# 3. Общие принципы

Успешность проекта определяется не количеством написанного кода, а достижением измеримых результатов.

Каждый критерий должен быть:

- измеримым;
- воспроизводимым;
- проверяемым;
- документированным.

---

# 4. Категории критериев

Успешность оценивается по следующим направлениям:

- продукт;
- инженерные расчёты;
- архитектура;
- производительность;
- качество;
- безопасность;
- масштабируемость;
- сопровождение;
- пользовательский опыт.

---

# 5. Критерии продукта

Платформа должна обеспечивать:

- проектирование лестниц различных типов;
- автоматический инженерный расчёт;
- автоматическую проверку ограничений;
- генерацию спецификаций;
- расчёт стоимости;
- экспорт результатов;
- сохранение проектов;
- повторное использование моделей.

---

# 6. Критерии инженерного ядра

Engineering Core считается успешным, если:

- расчёты детерминированы;
- отсутствуют некорректные геометрические модели;
- все ограничения проходят проверку;
- алгоритмы воспроизводимы;
- результаты трассируемы.

---

# 7. Архитектурные критерии

Архитектура считается успешной, если:

- соблюдены принципы Clean Architecture;
- соблюдены принципы DDD;
- отсутствуют циклические зависимости;
- соблюдены границы модулей;
- каждый модуль имеет единственную ответственность.

---

# 8. Критерии качества кода

Исходный код должен:

- соответствовать Coding Standards;
- иметь автоматические тесты;
- проходить Code Review;
- быть документированным;
- иметь минимальный технический долг.

---

# 9. Критерии производительности

Система должна:

- поддерживать масштабирование;
- эффективно использовать ресурсы;
- обеспечивать стабильную работу при росте нагрузки;
- поддерживать длительные инженерные расчёты без деградации.

Конкретные числовые показатели определяются в документах NFR.

---

# 10. Критерии безопасности

Платформа должна:

- обеспечивать разграничение доступа;
- защищать пользовательские данные;
- вести аудит действий;
- использовать безопасные механизмы аутентификации;
- соответствовать требованиям безопасности проекта.

---

# 11. Критерии тестирования

Успешной считается функциональность, которая:

- имеет Unit Tests;
- имеет Integration Tests;
- имеет Regression Tests;
- проходит автоматическую проверку;
- соответствует Acceptance Criteria.

---

# 12. Критерии документации

Документация считается успешной, если:

- соответствует STAIR-DOC;
- актуальна;
- имеет историю изменений;
- содержит диаграммы;
- содержит зависимости;
- содержит Acceptance Criteria.

---

# 13. Критерии сопровождения

Платформа должна:

- быть понятной новым разработчикам;
- иметь минимальную связанность;
- поддерживать независимое развитие модулей;
- иметь полную трассируемость требований.

---

# 14. Критерии расширяемости

Добавление:

- нового типа лестницы;
- нового материала;
- нового алгоритма;
- нового формата экспорта;
- нового AI-модуля;

не должно требовать изменения существующего инженерного ядра.

---

# 15. Критерии пользовательского опыта

Пользователь должен иметь возможность:

- создать проект;
- выполнить расчёт;
- получить объяснение ошибок;
- получить рекомендации;
- экспортировать результаты;
- сохранить проект.

Без необходимости знания инженерных расчётов.

---

# 16. Метрики проекта

Для оценки успешности используются:

- процент выполнения Roadmap;
- количество реализованных требований;
- покрытие тестами;
- количество архитектурных нарушений;
- количество открытых дефектов;
- количество технического долга;
- соответствие Acceptance Criteria.

---

# 17. Управление критериями

Все критерии должны регулярно проверяться.

Изменение критериев допускается только посредством ADR.
