# 1. Назначение

Настоящий документ определяет правила ведения журнала решений (Decision Log) проекта Stair Platform.

Decision Log фиксирует значимые решения, влияющие на развитие проекта, независимо от того, требуют ли они создания Architecture Decision Record (ADR).

Документ обеспечивает полную историю развития проекта.

---

# 2. Цель

Decision Log предназначен для:

- сохранения истории развития проекта;
- документирования ключевых решений;
- обеспечения прозрачности изменений;
- связи между требованиями, ADR и реализацией;
- упрощения анализа архитектуры.

---

# 3. Область применения

Decision Log используется для регистрации:

- архитектурных решений;
- инженерных решений;
- организационных решений;
- изменений Roadmap;
- изменений документации;
- изменений процессов разработки;
- изменений стандартов;
- значимых технических решений.

---

# 4. Отличие от ADR

ADR используется исключительно для архитектурных решений.

Decision Log фиксирует любые значимые решения проекта.

Не каждое решение требует ADR.

Каждый ADR обязательно отражается в Decision Log.

---

# 5. Структура записи

Каждая запись должна содержать:

- идентификатор;
- дату;
- название;
- категорию;
- краткое описание;
- основание;
- принятое решение;
- последствия;
- связанные документы;
- связанные ADR;
- связанные риски;
- статус.

---

# 6. Формат идентификаторов

Каждая запись получает уникальный идентификатор.

Формат:

```
DEC-0001
DEC-0002
DEC-0003
...
```

Нумерация непрерывная.

---

# 7. Категории решений

Допустимые категории:

- Architecture
- Engineering
- Documentation
- Development
- Infrastructure
- Security
- Database
- API
- Testing
- Performance
- Business
- AI
- Governance

---

# 8. Статусы

Каждое решение имеет один из статусов:

- Proposed
- Approved
- Implemented
- Rejected
- Archived

---

# 9. Связи

Запись Decision Log может ссылаться на:

- ADR;
- FR;
- NFR;
- CON;
- RISK;
- EDR (после внедрения);
- UML;
- ERD;
- API;
- исходный код;
- тесты.

---

# 10. Правила ведения

Decision Log обновляется:

- после утверждения ADR;
- после принятия важных инженерных решений;
- после изменения стратегии проекта;
- после изменения структуры документации;
- после изменения архитектуры;
- после изменения процессов разработки.

# 12. Управление журналом

Изменение существующих записей запрещено.

При необходимости создается новая запись.

История проекта должна быть неизменяемой.
