# 1. Назначение

Настоящий документ определяет критерии завершения разработки (Definition of Done, DoD) для Stair Platform.

Функциональность считается завершенной только после выполнения всех требований настоящего документа.

---

# 2. Цель

Definition of Done обеспечивает:

- единые критерии завершения разработки;
- высокое качество продукта;
- снижение технического долга;
- полноту документации;
- готовность функциональности к эксплуатации.

---

# 3. Общие принципы

Функциональность считается завершенной только при выполнении всех обязательных требований.

Частично выполненная задача не считается завершенной.

---

# 4. Реализация

Функциональность должна:

- соответствовать требованиям;
- соответствовать архитектуре;
- соответствовать инженерным принципам;
- соответствовать стандартам проекта.

---

# 5. Архитектура

Перед завершением должны быть подтверждены:

- отсутствие архитектурных нарушений;
- соблюдение границ модулей;
- отсутствие циклических зависимостей;
- соответствие утвержденным ADR.

---

# 6. Код

Исходный код обязан:

- успешно компилироваться;
- соответствовать Coding Standards;
- проходить Code Review;
- не содержать критических замечаний;
- не содержать дублирования;
- не содержать неиспользуемого кода.

---

# 7. Документация

Должны быть обновлены:

- STAIR-DOC;
- UML;
- ERD;
- API;
- ADR (при необходимости);
- CHANGELOG.

Документация должна соответствовать реализованной функциональности.

---

# 8. База данных

Если изменена модель данных, должны быть:

- подготовлены миграции;
- обновлена ERD;
- обновлены ограничения;
- проверена обратная совместимость.

---

# 9. API

Если изменен API, должны быть:

- обновлена спецификация OpenAPI;
- обновлены DTO;
- обновлены примеры запросов;
- обновлены примеры ответов;
- документированы новые ошибки.

---

# 10. Инженерные алгоритмы

Если реализованы инженерные расчеты, должны быть:

- подтверждена корректность алгоритма;
- проверены ограничения;
- подтверждена детерминированность;
- обновлена инженерная документация.

---

# 11. Тестирование

Функциональность должна пройти:

- Unit Tests;
- Integration Tests;
- Regression Tests (при необходимости);
- Contract Tests (для API);
- Geometry Tests (для инженерного ядра);
- Validation Tests (для Constraint Engine).

Все тесты должны завершиться успешно.

---

# 12. Производительность

Изменения не должны приводить к деградации производительности.

При необходимости выполняется нагрузочное тестирование.

---

# 13. Безопасность

Перед завершением проверяются:

- корректность авторизации;
- корректность разграничения доступа;
- обработка ошибок;
- защита API;
- отсутствие утечки чувствительных данных.

---

# 14. Критерии приемки

Все Acceptance Criteria должны быть выполнены.

Если хотя бы один критерий не выполнен — задача считается незавершенной.

---

# 15. Чек-лист Definition of Done

Перед закрытием задачи подтверждается:

- [ ] реализованы все требования;
- [ ] соблюдена архитектура;
- [ ] обновлена документация;
- [ ] обновлены UML;
- [ ] обновлена ERD (при необходимости);
- [ ] обновлен API (при необходимости);
- [ ] подготовлены миграции (при необходимости);
- [ ] выполнен Code Review;
- [ ] успешно пройдены все тесты;
- [ ] отсутствуют критические дефекты;
- [ ] выполнены Acceptance Criteria;
- [ ] обновлен журнал изменений.

---

# 16. Причины отказа

Задача не может считаться завершенной, если:

- отсутствуют тесты;
- отсутствует документация;
- имеются архитектурные нарушения;
- имеются критические ошибки;
- не выполнены Acceptance Criteria;
- имеются незакрытые блокирующие дефекты.

---

# 17. Управление DoD

Definition of Done пересматривается:

- при изменении архитектуры;
- при изменении процесса разработки;
- при изменении стандартов проекта.

Изменение настоящего документа допускается только посредством ADR.

# 19. Acceptance Criteria

Документ считается завершенным, если:

- определены критерии завершения разработки;
- определены требования к качеству кода;
- определены требования к документации;
- определены требования к тестированию;
- определены требования к безопасности;
- сформирован чек-лист DoD.
