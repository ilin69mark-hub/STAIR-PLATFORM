## S1 · SSRF и секреты вебхуков (высокий)

### S1-1 — SSRF в доставке исходящих webhook
- **Где**: `internal/infrastructure/integrations` (доставка webhook), SSRF-точка.
- **Проблема**: allowlist целей отсутствует/недостаточен; цель может указывать на
  `localhost`, `169.254.169.254` (metadata), приватные подсети.
- **Фикс**: 
  - DPI: не резолвить произвольные DNS имена → канонизация + блокировка
    loopback/link-local/private (аналогично `internal_only.go`).
  - Конфиг: `STAIR_WEBHOOK_ALLOW_HOSTS` (список разрешённых хостов) или
    проверка `HostnameAllowlist` на этапе конструирования доставки.
- **Done**: юнит-тесты на localhost/metadata/private-IP → отказ; публичные
  цели → успех; интеграционный тест «запрещённый хост не доставляется».
- **Риск**: совместимость с текущими интеграциями (проверить какие webhook
  используются, не сломать легальные исходящие).

### S1-2 — секреты вебхуков открытым текстом в Postgres (`SecretEnc`)
- **Где**: таблица интеграций, поле `SecretEnc` (секрет webhook-подписи).
- **Проблема**: секреты хранятся в открытом виде в БД.
- **Фикс**: AES-256-GCM шифрование на уровне приложения; мастер-ключ из env
  `STAIR_SECRETS_KEY` (16/32 байта); миграция для существующих строк.
- **Done**: `secrets` пакет + тесты round-trip; миграция не деградирует текущие
  интеграции; секрет не появляется в логах/API-ответе.

## S2 · Инфраструктура / деплой (высокий)

### S2-1 — безопасный runtime в k8s
- **Где**: helm-чарт (api + worker), `deploy/*`.
- **Проблема**: пустые `securityContext` и PDB.
- **Фикс**:
  - `securityContext`: non-root, `readOnlyRootFilesystem: true` (tmpfs для tmp),
    cap drop ALL, `seccompProfile: RuntimeDefault`.
  - PDB для api: `minAvailable: 1`; requests/limits на api и worker.
  - Горизонтальный autoscaler (HPA) при необходимости.
- **Done**: `helm template` без пустых securityContext; PDB задеплоен; e2e
  smoke: api живёт без прав root.

### S2-2 — единственный владелец инфраструктуры (helm ↔ terraform)
- **Где**: `deploy/terraform`, helm-чарты, CD-пайплайн.
- **Проблема**: двойное управление (terraform создаёт кластер, helm — ресурсы;
  конфиг-реалии расходятся).
- **Фикс**: зафиксировать в EDR: terraform = кластер/сеть/БД (infra), helm/CD =
  приложение (code-driven). Разрешить только одному приложению менять ресурсы,
  остальные перевести в read-only.
- **Done**: обновлённый EDR + разделение: никаких пересечений ресурсов в двух
  манифестах; CI-гейт «нет изменений в чужих ресурсах».

### S2-3 — supply-chain: фиксировать версии/диджесты
- **Где**: `.github/workflows`, docker-образы.
- **Проблема**: mutable actions-теги, `:latest` на images (main/develop).
- **Фикс**: actions по SHA (или зафиксированным major 2026), docker images по
  immutable-диджесту/SHAs с тегом версии (уже есть versioning в P3).
- **Done**: ни одного mutable-ссылки в workflows; гризли-гейт сборки использует
  digest; `docker-compose.yml` не тянет `:latest` в prod-профиле.

## S3 · Web / SEO / UX (средний)

### S3-1 — SEO и метаданные лендинга (store)
- **Где**: `frontend-store` (`index.html`, Landing).
- **Проблема**: SEO-ноль: нет title/OG/meta/schema.org.
- **Фикс**: базовый `<title>`, description, OG (точки из `VITE_CONTACT_*`),
  JSON-LD `Organization`/`LocalBusiness` + контакты.
- **Done**: lighthouse/robots check — title+meta+OG присутствуют; e2e smoke
  лендинга содержит уникальный title.

### S3-2 — обработка 401 в старых API-вызовах
- **Где**: фронты admin/store, устаревшие API-клиенты.
- **Проблема**: нет единой обработки 401 → неявные фолбэки.
- **Фикс**: централизованный интерцептор 401 → редирект на login
  (store: `#cabinet` → логин; admin: на логин),перебрасывание refresh-token.
- **Done**: e2e «сессия протухла → запрос вернул 401 → редирект на логин».

## S4 · Перф / безопасность фронта (средний)

### S4-1 — `jspdf` в стартовом чанке
- **Где**: `frontend` (admin), импорт `jspdf`.
- **Проблема**: тяжёлый чанк тянется при старте.
- **Фикс**: dynamic `import('jspdf')` в месте генерации КП; проверить бандл
  (target < ~300K gzip главного чанка, GeometryViewer можно так же ленить).
- **Done**: главный чанк < порога; jspdf в отдельном lazy-чанке.

### S4-2 — rate-limit за прокси: зафиксировать решение в EDR
- **Где**: `internal/transport/http/middleware_auth.go` (`clientIP`), EDR-0014.
- **Проблема**: за proxy все запросы = 1 IP (`RemoteAddr`-only, осознанно).
- **Фикс (инфра-решение)**: на nginx/LB пробросить real IP за доверенным
  прокси (X-Forwarded-For + `X-Real-IP`) и настроить список доверенных прокси
  в приложении; задокументировать в EDR-0014.
- **Done**: EDR-0014 дополнен; документируем поведение, без кода, пока нет
  реального прокси в проде.
